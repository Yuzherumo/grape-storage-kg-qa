# 已知限制

本文列出当前系统明确不能保证或尚未验证的能力，用于技术评审与后续规划。数据与验证结果见 [data.md](data.md)、[validation.md](validation.md)。

## 1. 知识覆盖范围

- **品种**：仅 8 个（阳光玫瑰、巨峰、红地球、夏黑、玫瑰香、克瑞森无核、户太八号、维多利亚）。品种的耐贮性、SO₂ 敏感性、适宜条件等存在产地、栽培方式和年份差异，图谱只保留文献中可引用的区间/描述。
- **病害**：7 种（灰霉、根霉腐败、青霉、炭疽、酸腐、黑斑、绿霉），其中炭疽病、酸腐病主要依赖综述/植物病理学通识，条文级证据不足。
- **储藏条件**：30 个，覆盖温度、湿度、气调、预冷、包装、保鲜剂、入库/码垛、销售与档案等；不是完整的冷链操作规程。
- **品质指标**：13 个，且多数品种没有完整基线（例如玫瑰香的耐贮性为空）。
- 图谱是**演示级知识库**，不是全品种、全病害、全产区的权威数据库。

## 2. 数据规模与证据等级

- 三元组共 108 条：`verified` 61、`anchor` 47。
- 47 条 anchor 的原文未获取，只在 `note` 标明待核验点；其中 36 条依赖同一篇未取得的 2024 综述、16 条依赖包装工程综述。它们不能被视为已经核实的结论。
- 61 条 verified 中，51 条按 GB/T 16862-2026 条文升级、10 条按用户提供的 5 篇综述原文升级；标准只保留条级摘录，未转载全文。
- `confidence` 是人工设定的来源置信度，不是统计概率；排序权重（verified 1.0 / anchor 0.6）同样是工程选择。
- 部分来源题录不完整（缺少作者、DOI 或年份），已按可得信息登记，未补全的不编造。
- 科普描述（28 个节点）来自科普中国、百度百科与国标，属于**改写引用**，不是原文；它用于帮助理解，不作为条文级证据。

## 3. 大语言模型的不确定性

- 在线模式依赖外部 OpenAI 兼容服务（默认 DeepSeek），回答受模型版本、网络、限流与随机性影响，同一问题可能得到不同表述。
- 提示词要求「只依据证据、逐结论标注 `[E#]`」，但模型仍可能遗漏引用、错误归因或把两条证据混在一起。
- 当前通过规则校验（引用存在性、引用与句子字面匹配、数字来源/区间、anchor 高风险参数拦截）降低风险，并允许一次纠正后回退模板；这不是语义级事实验证，仍可能漏判或误判。
- 离线模板模式不调用模型，表达较固定，复杂问题可能只给出证据要点而不是自然语言解释。

## 4. 引用与数值校验的能力边界

- 引用校验检查 `[E#]` 是否存在于本轮证据、是否与事实句有字面/数值关联；不判断引用是否在语义上支持该结论。
- `check_numbers()` 按单位族与区间比对，能发现证据外数字、超出温度区间的数字；对单位换算、复合单位、隐含数值（如「两三天」）覆盖有限。
- `out_of_range` 主要针对温度类问题；其他单位的越界判断依赖证据区间，规则并不完备。
- `anchor_high_risk` 只拦截「仅凭 anchor 证据给出药剂/浓度/剂量/处理时间」的情况，不能覆盖所有高风险表述。
- 因此系统可以做到「数字有来源、引用可核对」，但不能保证「答案在农艺上一定正确」；最终操作应结合产品标签、当地技术员与实际情况。

## 5. 在线与离线模式差异

| 维度 | 离线模板 | 在线 LLM |
|---|---|---|
| 依赖 | 无网络、无 Key | 需要 Key 与可访问的 API |
| 表达 | 模板拼装，句式固定 | 自然语言，可能更易读 |
| 风险 | 低（确定性） | 模型幻觉、限流、超时、版本变化 |
| 校验 | 引用 + 数字校验 | 额外规则校验与一键回退 |

两种模式共享同一套证据与拒答逻辑；在线模式失败会自动回退模板，但用户看到的告警与回答风格会不同。

## 6. Neo4j 与图数据库验证的限制

- 官方 Neo4j 分发包在当前网络被 403 拦截，本机也没有 JDK 21/Aura 账号，因此**没有启动 Neo4j 服务端**；双后端一致性测试处于 skipped。
- 替代验证是：Cypher 静态校验 + 嵌入式 openCypher 引擎 Kùzu 实跑 + 便携版安装脚本（拿到 zip 后可复现导入）。
- Kùzu 不是 Neo4j：约束、事务、并发、Bolt/HTTP 服务、Neo4j 特有函数与执行计划均未被验证；Cypher 模板在 Neo4j 上的实际执行仍需后续确认。
- 本地后端是默认路径，演示与测试均以本地后端为准。

## 7. 系统与部署限制

- 公网 Demo 部署在魔搭创空间免费 CPU 实例：空闲会休眠，首次访问冷启动数十秒；并发能力有限。
- 在线模式需要外部 API 可用；API Key 只存在本地 `.env` 或平台环境变量中，不随仓库分发。
- 仓库脚本以 Windows PowerShell 为主（`install.ps1`、`run.ps1`、打包与便携 Neo4j 脚本）；Linux/macOS 仅提供手动命令，未在 Linux 实机验证安装脚本。
- 当前远端 GitHub Actions 在 Kùzu 步骤失败（CI 环境找不到 `app` 包），修复已在本地工作区但未推送；仓库 CI 尚不能作为「全绿」证据。
- UI 回归使用 Streamlit `AppTest` 与安全测试，没有真实浏览器像素级验证；仓库中的界面截图来自真实运行实例，但不是自动化截图。

## 8. 功能边界

- 意图路由为规则实现，覆盖 10 类意图；超出这些意图的问题可能被归为 `general` 或被拒答。
- 多轮上下文只在「明确指代式追问」时继承上一轮实体；复杂对话、跨话题切换、代词消解能力有限。
- 不提供语音输入、图像识别、实时 IoT 数据、库存管理、病害图像诊断，也不做处方级药剂推荐。
- 不做用户账户、权限、审计日志与多租户；公网实例为公开演示。
- 图谱可视化用于理解与展示，节点布局是确定性力导向结果，不代表知识层次或因果强度。

## 9. 不能保证的事项

1. 不能保证覆盖用户所在产区、品种与年份的全部规范；
2. 不能保证 47 条 anchor 对应的结论正确，它们仍待原文核验；
3. 不能保证大模型回答在语义上完全忠实于证据；
4. 不能替代农技员、冷库技术负责人或官方标准的最终解释；
5. 不能保证公网 Demo 长期在线、低延迟或高并发；
6. 不能保证当前仓库 CI 为绿色（见第 7 节）。

如果以上限制影响评审判断，请以 `data/` 中的原始数据、`docs/sources.md` 的引文与 `docs/validation.md` 的实际运行记录为准。
