# 作品简介（200 字版 + 一页要点）

## 200 字简介（提交用，正文 198 字）

鲜食葡萄采后损耗，不是技术不够，而是规范没人读得下去。我们把现行国标 GB/T 16862-2026 与综述中的储藏规范拆成 59 节点、71 条三元组的知识图谱：品种、储藏条件、品质指标、病害互连，每条带来源与定位。农户和冷库管理员用大白话问「阳光玫瑰放冷库几度」「葡萄长白毛咋办」，系统先识别品种与病害再查图谱，让大模型只能引用证据生成「结论＋依据＋现在该做什么」，数字可溯源；没收录就直说，断网也能用。

> 若平台按「汉字数」统计（不含数字与标点）约 165 字，仍满足 200 字上限。

## 一页要点（答辩 / 推文用）

**一句话**：把葡萄储藏国标做成农户问得出、听得懂、查得到来源、还能照做的知识图谱问答。

**痛点**：采后损耗高，参数靠经验；SO₂ 用错会毁货；灰霉爆发不知从哪下手；不知道什么时候该出库。

**怎么做的**
1. 图谱：5 类实体 59 节点、9 种关系 71 条边，条级溯源（`source_ids + locator + quote + status`），拿不到原文的标「待核验」；
2. 问答：实体链接 → 意图路由 → 参数化查图 → 证据编号 → DeepSeek 只依据证据生成「结论/依据/现在该做什么」；
3. 可信：引用校验 + 数值一致性（单位/±区间/越界）双层拦截，越界问题直接说不可行；
4. 可用：口语/错别字容错、大字模式、无 API Key/断网自动降级模板模式。

**硬指标**
- 离线可复现评测：核心题 5/5、越界探针 1/1、12 条农户口语意图命中 12/12；
- 测试：`pytest tests -q` → 96 passed / 2 skipped（无网可跑）；
- 图谱：59 节点 / 71 条关系 / 10 个查询模板；数据十项校验全绿。

**差异化（相对普通 RAG）**
检索单位是三元组而不是文本块 → 能做品种对比、禁忌/替代推理、区间越界判断；每条证据可点到来源与核验状态。

**目标用户**：种植户/合作社（入库参数）、冷库管理员（巡检处置）、采购质检（到货判定）、农技员与学生（学习对比）。

**技术栈**：Python 3.12 + Streamlit + DeepSeek（OpenAI 兼容）+ 纯标准库图检索；Neo4j Cypher 脚本完整交付（可选后端）。

**赛道**：农客松 2026 · 主赛道 · 方向二「生命系统」。
